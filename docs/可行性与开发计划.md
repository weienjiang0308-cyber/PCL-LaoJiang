# PCL 第三方启动器可行性与开发计划

研究日期为 2026 年 10 月 26 日。技术上可以重新建立下载和安装功能，并尽量保持熟悉的操作流程。工作量主要来自下载源接入、不同版本和加载器的兼容、依赖解析，以及失败恢复；恢复一个按钮并不代表完成整套功能。

## 已确认的现状

[PCL 2.99.0.0 的官方提交](https://github.com/Meloong-Git/PCL/commit/e4b0489a22cfd4bc57a18fc1e2ac66d5c18e7fc1)明确记录移除 MC 下载功能。[PCL CE 2.15.1 发布说明](https://github.com/PCL-Community/PCL-CE/releases/tag/v2.15.1)记录中国大陆地区禁用 Minecraft 安装功能。因此，单纯换成当前社区版不能保证实现恢复下载的目标。

本机桌面 `PCL` 目录留存的日志记录过 Release 2.10.9，但未找到该日志所指向的桌面启动器 EXE，无法据此确认现在实际使用的版本。后续以实际 EXE 的版本和可复现行为为准。

## 候选开发基础

优先评估 PCL CE `v2.15.1`，参考提交为 `1a7653127d578efdb2a9388999a3fdc67d9e49d5`。它保留了界面、版本隔离、资源管理及组件安装等较完整的实现，适合追求原有使用体验的目标。

复用边界必须按目录确认。其根目录的 Apache 2.0 许可不覆盖 `Plain Craft Launcher 2/`，该目录使用 PCL 自定义许可。依据该目录的[许可及合理使用指南](https://github.com/PCL-Community/PCL-CE/blob/v2.15.1/Plain%20Craft%20Launcher%202/LICENCE)，重度复用涉及第三方标识、名称、署名、源码公开和特定界面及启动行为要求。指南自称说明而非法律协议，不能把它等同于通用开源授权；具体复用和分发方案应对应原文逐项落实。

如果这些条件与最终产品目标冲突，可改为独立实现界面与下载模块，并逐项选择许可明确的可复用组件。当前仅保留原样参考源码，尚未决定完整派生发行版的复用范围和正式名称。

## 功能和下载来源

这里将用户提到的“官方模组”理解为从模组作者发布的平台获取模组。社区模组和光影包不属于 Mojang 官方内容；界面应明确显示来源。

| 功能 | 候选来源 | 实现重点 | 顺序 |
| --- | --- | --- | --- |
| 原版正式版及快照 | Mojang 官方版本清单和清单内下载地址 | 客户端、库、资源索引、资源文件、规则和原生库 | 第一阶段 |
| 国内加速镜像 | BMCLAPI 等明确允许接入的镜像 | 按资源类型映射、校验、超时回退、来源显示 | 第二阶段 |
| Fabric | Fabric 官方元数据和 Maven | 匹配游戏版本和安装器版本 | 第一阶段 |
| Forge 与 NeoForge | 各自官方 Maven 和元数据 | 安装器及处理器、Java 版本、合并版本 JSON | 第二阶段 |
| 模组 | 优先 Modrinth，后接 CurseForge | 游戏版本及加载器筛选、必需依赖、更新 | 第一至二阶段 |
| 光影包 | Modrinth 及支持相应资源的发布平台 | 安装至实例 shaderpacks，提示适配的光影加载环境 | 第一阶段 |
| 资源包 | Modrinth、CurseForge | 安装至实例 resourcepacks，提示兼容范围 | 第一阶段 |
| 整合包 | Modrinth 和 CurseForge 清单、本地导入 | 解包路径检查、依赖下载、实例隔离 | 第二阶段 |
| Java 自动准备 | 对应版本元数据及可信发行源 | 架构、版本要求、来源校验、解压 | 第二阶段 |
| 账号与启动 | 微软账号与正版授权流程、本地实例 | 第三方应用身份配置、授权验证、启动参数 | 随基础启动验收 |
| 旧组件及扩展功能 | 原有功能对应维护方 | OptiFine、Quilt、LiteLoader 等逐项核实适配和分发条件 | 第三阶段 |

Mojang 官方源与 BMCLAPI 社区镜像分别标识，避免将第三方镜像称为“官方镜像”。[BMCLAPI 文档](https://bmclapidoc.bangbang93.com/)列出了地址映射和使用要求，包含可视来源标注。

[Modrinth API](https://docs.modrinth.com/api/)要求可识别的 User-Agent，并提供项目搜索与版本等接口。[CurseForge API](https://docs.curseforge.com/rest-api/)使用 API Key；后续需配置本项目获准使用的凭证，并处理资源不提供第三方下载地址的情形。不从其他启动器中提取密钥，无法直接下载的资源提供原发布页入口。

## 下载和安装设计

界面发起安装请求后，由资源提供器获取元数据，兼容性解析器生成完整下载计划，再交给统一下载队列。文件通过清单给出的哈希和大小校验后写入临时安装目录，完整安装成功后提交为可用实例。

下载队列统一处理并发上限、有限重试、取消、进度、缓存和错误信息。只有服务器支持 Range 且文件身份可确认时才断点续传。服务器明确拒绝访问时显示原因，不把这种拒绝当成普通网络超时无限换源。

镜像转换按已知来源和资源类型分别实现，不能将所有 URL 简单替换成一个域名。登录请求和授权令牌只发送至对应认证服务，下载日志应移除令牌等敏感字段。

实例维持独立的 `mods`、`shaderpacks`、`resourcepacks` 和配置目录。开发测试使用项目沙盒，不直接写入现有游戏目录。更新启动器时使用本项目独立更新来源，避免第三方构建被上游更新覆盖。

## 恢复顺序与验收

### 第一阶段完成一条完整安装流程

1. 配置 .NET 10 SDK，构建未修改的参考版本，记录构建依赖和缺失配置。
2. 确定派生版本的复用范围、名称、署名及许可落实方式。
3. 在独立运行目录中获取官方版本列表，安装一个正式版并验证合法账号启动。
4. 实现 Fabric 和一个匹配模组的安装，再安装一个光影包和资源包。

验收时应从干净沙盒完成上述操作，文件安装位置正确，版本筛选和依赖提示有效，取消或失败后不会留下被误认为成功的实例。光影包验收包括对应光影加载环境可用，不能只检查 ZIP 已保存。

### 第二阶段补齐常用兼容性

加入镜像回退、Forge、NeoForge、Java 准备、整合包导入、资源更新和缓存。覆盖受支持范围内的新旧代表版本，验证错误哈希、网络中断、文件占用、中文路径和必需依赖缺失的处理。

### 第三阶段核对原有功能

建立原版 PCL 与第三方版本的逐页功能对照，补齐搜索、收藏、下载任务管理、版本修改、资源管理等行为；扩展组件逐项确认。发布前保留可复现构建说明、依赖及许可清单和独立更新机制。
